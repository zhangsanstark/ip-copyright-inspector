基础类型与容器

问：input 返回什么类型？

答：成功读取时返回字符串。要数字就显式使用 int 或 float 转换；读到输入结束时会抛出 EOFError。

问：常见可变容器有哪些？

答：list、dict、set。它们可以在原对象上增加、删除或修改内容。

问：str 和 tuple 为什么叫不可变？

答：对象创建后不能原地改内容。所谓“修改”通常是创建新对象并重新绑定名称。

问：append 和 extend 的区别是什么？

答：append 整体塞进一个格子；extend 打开可迭代对象，逐个塞进去。

问：为什么单元素元组必须写逗号？

答：括号主要负责分组，逗号才真正表示元组，所以写成 `(10,)`。

问：dict 现在有顺序吗？

答：现代 Python 保留插入顺序，但业务查找仍应依赖键，不要把字典当列表使用。

问：字典方括号和 get 怎么选？

答：键必须存在用方括号；键允许缺失用 get。不要为了不报错而一律使用 get。

问：set 适合做什么？

答：去重和集合运算。它没有普通列表那样的位置下标。

问：切片为什么叫包头不包尾？

答：start 位置会取，stop 位置不取。步长为 1 且边界有效时，长度等于 stop 减 start；其他情况要结合实际步长和边界判断。

问：最常见的序列反转写法有哪些？

答：`values[::-1]` 创建反向副本，列表的 reverse 原地修改，reversed 返回惰性反向迭代器。按是否保留原对象来选。

问：zip 遇到不同长度怎么办？

答：默认在最短输入结束时停止，多出的元素不会自动补齐。

问：列表推导式里的 if 和三元表达式有何区别？

答：末尾 if 用来筛掉元素；前面的 A if condition else B 用来替换元素，通常不改变数量。

问：copy 为什么还会互相影响？

答：list.copy 和切片只复制外层。内部可变对象仍可能共享，需要时使用 deepcopy 或重新设计数据结构。

问：等号和 is 怎么选？

答：比较值用等号；比较是否同一对象用 is。检查 None 使用 is None。

函数与作用域

问：return 多个值实际返回什么？

答：自动打包成一个元组，调用方可以再拆包。

问：global 是干什么的？

答：告诉 Python，函数内的赋值要重新绑定模块全局名称。

问：nonlocal 是干什么的？

答：告诉内层函数，赋值要修改最近一层外部函数的名称。

问：`*args` 收到什么？

答：多余的位置参数被收成元组。

问：`**kwargs` 收到什么？

答：多余的关键字参数被收成字典。

问：调用时位置参数和关键字参数如何排列？

答：普通位置参数写在普通关键字参数前。复杂拆包规则另看函数专题，不要靠猜。

问：可变默认参数为什么危险？

答：默认对象只创建一次，多次调用会共享。常用修复是默认写 None，函数内部再新建容器。

问：循环 lambda 为什么常得到最后一个值？

答：闭包在真正调用时才查变量。可用默认参数 `i=i` 固定当轮值。

问：什么时候适合 lambda？

答：只适合很短的一次性表达式，常用于 sorted 或 sort 的 key。逻辑复杂就写 def。

问：多字段排序如何写？

答：让 key 返回元组。数字字段需要局部降序时，可对该字段取负数。

问：类型提示会自动拦截错误类型吗？

答：默认不会。它主要帮助编辑器、检查工具和读代码的人；边界校验交给 Pydantic 或显式代码。

Python 风格工具

问：装饰器一句话是什么？

答：接收一个函数，返回一个新函数，再把原名称绑定到新函数上。

问：装饰器包装函数为什么常写 `*args` 和 `**kwargs`？

答：为了透明转发不同形状的参数，不把被装饰函数限制死。

问：为什么要用 functools.wraps？

答：它保留原函数的名称、说明和其他元数据，方便日志、调试和框架识别。

问：闭包一句话是什么？

答：函数离开创建位置后，仍能记住并使用外层函数里的变量。

问：with 解决什么问题？

答：成功进入上下文后，保证资源用完就清理，即使中间抛异常也会执行退出逻辑。

问：`__exit__` 返回 True 有什么效果？

答：表示异常已经处理，不再向外抛。除非非常确定，否则不要随便吞掉异常。

问：yield 做了什么？

答：`yield` 产出一个值并暂停；下次迭代时从暂停处继续。`return` 则会结束生成器。

问：生成器为什么省内存？

答：它通常一次只产生一个值，不必先把全部结果装进列表。具体节省多少取决于用法。

问：推导式和生成器表达式的符号区别？

答：列表推导式用方括号并立即生成列表；生成器表达式用圆括号并按需产生值。

面向对象

问：Python 实例化为什么没有 new？

答：直接调用类即可。对象创建和初始化细节由类的调用协议处理，日常主要编写 `__init__`。

问：self 是什么？

答：当前实例本身，类似 Java 的 this，但必须显式写进实例方法参数。

问：鸭子类型一句话是什么？

答：只要对象提供需要的方法，就可以使用，不强制先声明实现某个接口。

问：property 什么时候值得写？

答：需要校验、计算、只读控制或兼容旧接口时。普通公开字段不必机械包装。

问：property 无限递归怎么发生？

答：setter 内再次写同名公开属性，或 getter 内再次读同名公开属性，都会调用自己。内部存储应使用不同名称，例如 `_value`。

问：`__str__` 和 `__repr__` 的分工是什么？

答：str 面向普通展示，repr 面向开发和调试，尽量提供明确、可辨认的信息。

问：`__call__` 有什么作用？

答：让实例可以像函数一样被调用，适合封装带状态的策略或处理器。

问：`__getitem__` 会收到什么？

答：普通索引时收到索引值，切片时收到 slice 对象。

问：类变量和实例变量如何区分？

答：类体中定义的值默认由类共享；通过 self 赋值通常建立当前实例自己的值。

问：MRO 是什么？

答：多重继承时的方法查找顺序。使用类的 mro 方法查看，不要凭肉眼猜复杂继承关系。

问：什么时候优先组合而不是继承？

答：当两个对象只是合作关系，不是真正的“属于同一种类型”时，组合通常更清楚。

并发

问：并发和并行的区别？

答：并发是多项任务交替推进；并行是同一时刻真的在多个核心上执行。

问：默认 CPython 的 GIL 有什么影响？

答：同一进程里通常只有一个线程执行 Python 字节码，所以纯 Python 的 CPU 密集线程难以多核加速。

问：GIL 是否代表永远不能线程并行？

答：不是。原生扩展可能释放 GIL，Python 3.13 起也有可选 free-threaded 构建，但要按解释器和依赖实际验证。

问：I/O 密集任务为什么适合线程？

答：线程等待网络、磁盘等 I/O 时，其他线程可以继续工作。

问：CPU 密集任务通常选什么？

答：默认 CPython 下优先考虑多进程、释放 GIL 的原生库或独立计算服务。

问：高并发异步 I/O 通常选什么？

答：asyncio 和原生异步库。它适合大量等待，不适合直接承载长时间 CPU 计算。

问：await 是什么信号？

答：等待对象尚未完成时，await 让当前协程暂停，事件循环可以去推进其他任务。

问：async def 里能直接 time.sleep 吗？

答：不应这样做，它会阻塞事件循环。异步等待使用 asyncio.sleep。

问：Windows 多进程最重要的保护是什么？

答：把启动入口放进 `if __name__ == "__main__":`，避免子进程重复导入时递归启动。

问：十万并发连接是 asyncio 的保证吗？

答：不是。实际能力还受内存、文件描述符、连接池、超时、框架和操作系统影响。

后端工程化

问：Pydantic 最适合放在哪里？

答：放在系统边界，把不可信输入转换和校验成符合已声明结构的数据。它不能保证业务事实一定真实。

问：Pydantic 2 常用的输出方法是什么？

答：model_dump 返回字典，model_dump_json 返回 JSON 字符串。

问：FastAPI 为什么能自动生成接口文档？

答：它读取路由、类型提示和 Pydantic 模型，生成 OpenAPI 描述，再展示交互式文档。

问：FastAPI 路由应该写 def 还是 async def？

答：调用可 await 的异步库时写 async def；只能调用阻塞库时可写普通 def，让框架在线程池处理。

问：SQLAlchemy 2 查询的核心写法是什么？

答：使用 select 构造语句，再由 Session 或 AsyncSession 执行。

问：AsyncSession 能交给多个 gather 任务共享吗？

答：不要。每个并发任务应拥有自己的 Session 和事务范围。

问：SQLite 加 aiosqlite 是否等于真正的网络异步数据库？

答：不是。aiosqlite 主要通过后台线程包装 SQLite，适合演示和小型场景。

问：pyproject.toml 类似 Java 的什么？

答：可粗略类比 pom.xml 或 build.gradle，集中放项目元数据、依赖和工具配置。

问：uv.lock 是否应该提交？

答：应用项目通常应提交，以便不同电脑得到可重复的依赖版本。

问：pytest 为什么常直接使用 assert？

答：pytest 会重写 assert，失败时展示更清楚的表达式差异。

问：Uvicorn 是什么？

答：运行 ASGI 应用的服务器，开发时可配 reload，生产部署还要考虑进程数、代理和监控。

问：示例项目的相似度分数代表侵权吗？

答：不代表。它只是文本特征的技术比较结果，不能替代版权归属、授权范围和法律判断。

最后五句口诀

- 容器先分可变不可变，查改删增再选方法。
- 参数默认别放可变，循环闭包记得锁值。
- 资源清理交给 with，大数据流水线想到 yield。
- 纯计算看进程，阻塞等待看线程，全异步等待看 asyncio。
- 类型提示管表达，Pydantic 管入口，测试管回归。
