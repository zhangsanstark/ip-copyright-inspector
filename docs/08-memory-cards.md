1）基础类型与容器

1.1 input() 读到的为什么不是数字？

答：input() 把输入当作文本。输入 18，拿到的是 `"18"`，需要计算时再用 `int()` 或 `float()` 转换。它成功读取时返回字符串；读到输入结束时会抛出 EOFError。

1.2 哪些容器可以原地改内容？

答：list、dict、set。它们可以在原对象上增加、删除或修改内容。

1.3 str 和 tuple 为什么叫不可变？

答：字符串不能原地改某个字符，元组不能替换某个位置的元素。给变量重新赋值，只是让变量指向另一个对象。注意元组里如果放了列表，列表自己的内容仍然能改。

1.4 append 和 extend 到底差在哪？

答：从 `[1, 2]` 开始，`append([3, 4])` 得到 `[1, 2, [3, 4]]`；`extend([3, 4])` 得到 `[1, 2, 3, 4]`。前者把传入内容当成一个元素，后者逐个加入里面的元素。

1.5 单元素元组为什么要写成 (10,)？

答：括号主要负责分组，逗号才真正表示元组，所以写成 `(10,)`。

1.6 字典有顺序，为什么又说它没有位置下标？

答：现代 Python 会按插入顺序遍历字典，但取值仍然靠键。`data[0]` 查的是键 0，不是第一个值；没有这个键就会报 KeyError。

1.7 取字典里的值，用方括号还是 get？

答：必须有的键用 `data[key]`，缺失时让错误暴露出来；允许没有的键用 `data.get(key, 默认值)`。键不存在且没指定默认值时，返回 None。不要为了“不报错”就把所有取值都换成 get。

1.8 什么情况下会想到 set？

答：去重和集合运算。它没有普通列表那样的位置下标。

1.9 切片的“包头不包尾”怎么理解？

答：比如 `values[1:4]` 取下标 1、2、3，不取 4。步长为 1、边界又在有效范围内时，长度就是 `4 - 1 = 3`；遇到越界、负步长等情况，不能只做这个减法。

1.10 想把序列倒过来，有哪几种写法？

答：`values[::-1]` 创建反向副本，列表的 reverse 原地修改，reversed 返回惰性反向迭代器。按是否保留原对象来选。

1.11 zip 的两边长度不同，会报错吗？

答：默认不报错，短的一边用完就停止。`zip([1, 2], ["a"])` 只产生 `(1, "a")`，不会给 2 自动补搭档。

1.12 推导式里的两个 if，为什么位置不一样？

答：`[x for x in values if x > 0]` 是筛选，不符合的直接不要；`[x if x > 0 else 0 for x in values]` 是替换，不符合的变成 0，元素数量不变。先问自己“是删掉，还是换一个值”，位置就好选了。

1.13 明明 copy 了，为什么修改后还会互相影响？

答：`list.copy()` 和切片只复制外面那层列表。假如元素也是列表，两份外层列表仍可能装着同一个内层列表。修改内层内容，两边都会看到；确实需要相互独立时，再考虑 deepcopy 或调整数据结构。

1.14 == 和 is，分别在问什么？

答：`==` 问“值是否相等”，`is` 问“是不是同一个对象”。两个分别创建的 `[1, 2]` 可以值相等，却不是同一个列表。检查 None 写 `value is None`。

2）函数与作用域

2.1 return a, b 真的是返回了两个对象吗？

答：它返回的是一个元组 `(a, b)`。调用方写 `x, y = func()`，是在把这个元组拆开，分别交给 x 和 y。

2.2 global 改的是哪一个变量？

答：它告诉 Python：“这里赋值用的是模块里的那个变量，不要另建同名局部变量。”比如改全局计数 `count += 1` 需要声明；只是向全局列表 `items.append(1)`，没有给变量 items 重新赋值，通常不需要。注意 `items += [1]` 也包含赋值，不能与 append 混为一谈。

2.3 nonlocal 和 global 有什么区别？

答：global 找模块里的变量；nonlocal 找外层函数里已经存在的变量，有多层时找最近的那层。内层函数要更新外层计数器，常用 nonlocal。

2.4 定义函数时，`*args` 收到什么？

答：多余的位置参数被收成元组。

2.5 定义函数时，`**kwargs` 收到什么？

答：多余的关键字参数被收成字典。

2.6 调用函数时，参数先写谁、后写谁？

答：普通写法先位置、后关键字，比如 `create_user(1, name="Ada")`。涉及 `*values`、`**options` 的拆包，以及定义中的 `/`、`*` 时，再按函数专题里的具体规则判断。

2.7 默认参数写 []，为什么第二次调用还留着上次的数据？

答：默认列表是在定义函数时创建的，不是每次调用时新建的。不传这个参数的调用会共用它。常见修复是默认写 None，再在函数内部判断并新建列表。

2.8 循环里建的 lambda，为什么结果都一样？

答：函数被创建时，不会自动拍下循环变量的值；真正调用时才去找它。这时循环通常已经结束，变量留在最后一个值。`lambda x, i=i: x + i` 利用默认参数保存创建当时的 i；如果保存的是可变对象，它仍然是对象引用，不是深拷贝。

2.9 什么情况写 lambda，什么情况写 def？

答：只适合很短的一次性表达式，常用于 sorted 或 sort 的 key。逻辑复杂就写 def。

2.10 先按销售额降序，再按年龄升序，怎么排？

答：让 key 返回元组，例如 `key=lambda x: (-x["sales"], x["age"])`。先比较销售额，只有销售额相同才比较年龄；这里的负号只反转数值销售额的顺序，不影响年龄。

2.11 写了参数类型，传错类型就一定报错吗？

答：默认不会。它主要帮助编辑器、检查工具和读代码的人；边界校验交给 Pydantic 或显式代码。

3）装饰器、闭包、with 和生成器

3.1 装饰器做了什么？

答：常见用法是在原函数外加一层处理，比如先记日志、再调用原函数。`@deco` 相当于定义函数后执行 `func = deco(func)`；平时最常见的是返回包装函数，但装饰器不只限于这一种返回结果。

3.2 包装函数为什么常写 `*args` 和 `**kwargs`？

答：它不知道原函数以后会接几个参数、叫什么名字，所以先把参数接住，再用 `func(*args, **kwargs)` 原样传过去。别忘了把原函数的返回值 return 出去。

3.3 明明能运行，为什么还要加 functools.wraps？

答：包了一层以后，日志里可能只看见 wrapper，而不是原函数名。wraps 会保留原函数的名称、说明等信息，方便调试，也方便框架识别。

3.4 外层函数都返回了，内层函数怎么还能用它的变量？

答：返回的内层函数仍保留着对外层变量的引用，这就是闭包。比如创建一个“每次加 2”的函数，创建它的外层函数结束后，它仍然知道要加的是 2。

3.5 with 帮我省掉了什么？

答：省掉每次手写资源清理的重复代码。成功进入 with 后，正常退出或因异常离开时，都会调用退出逻辑，例如关闭文件；不包括进程被强制终止等无法继续执行代码的情况。

3.6 `__exit__` 返回 True，异常去哪了？

答：表示异常已经处理，不再向外抛。除非非常确定，否则不要随便吞掉异常。

3.7 yield 和 return 都交出一个值，差别是什么？

答：`yield` 产出一个值并暂停；下次迭代时从暂停处继续。`return` 则会结束生成器。

3.8 生成器为什么可能省很多内存？

答：它通常一次只产生一个值，不必先把全部结果装进列表。具体节省多少取决于用法。

3.9 方括号换成圆括号，行为有什么变化？

答：列表推导式用方括号并立即生成列表；生成器表达式用圆括号并按需产生值。

4）对象与属性

4.1 不写 new，怎样创建对象？

答：直接写 `User()`。创建对象的机制由类负责，日常通常在 `__init__` 里给实例设置初始属性。注意 `__init__` 负责初始化，不是创建对象本身。

4.2 self 指的是谁？

答：当前实例本身，类似 Java 的 this，但必须显式写进实例方法参数。

4.3 没声明实现接口，也能传进去用吗？

答：可以，这就是常说的鸭子类型。调用方需要 `obj.send()`，对象只要提供能按约定工作的 send 方法，就可以参与；如果没有，运行到调用处才会报错。

4.4 什么情况下值得加 property？

答：需要校验、计算、只读控制或兼容旧接口时。普通公开字段不必机械包装。

4.5 property 为什么会不停调用自己？

答：给 `value` 写了 setter，又在里面执行 `self.value = x`，就会再次进入同一个 setter，一直重复直到 RecursionError。getter 里再读 `self.value` 也类似。内部存储改用 `_value`，对外才使用 value。

4.6 `__str__` 和 `__repr__`，分别给谁看？

答：str 面向普通展示，repr 面向开发和调试，尽量提供明确、可辨认的信息。

4.7 为什么一个对象也能像函数那样写 obj()？

答：在类中实现 `__call__`，实例就可以像函数一样被调用。例如 `checker(text)` 可以一边使用对象保存的配置，一边处理 text，适合需要保留状态的处理器。

4.8 obj[2] 和 obj[1:4]，传给 `__getitem__` 的是什么？

答：前者收到整数 2，后者收到 `slice(1, 4, None)`。如果要支持两种访问方式，就要分别处理索引和 slice。

4.9 为什么改了一个对象，另一个对象也受影响？

答：先检查是不是把可变数据放成了类变量。类体里的 `items = []` 默认由实例共享；在 `__init__` 中写 `self.items = []`，每次创建实例才会得到自己的列表。给某个实例属性重新赋值和修改共享列表，也不是同一回事。

4.10 多个父类都有同名方法，最终调用哪一个？

答：按 MRO，也就是这个类的方法查找顺序。用 `MyClass.mro()` 直接查看，别只看某个父类的书写位置来猜。`super()` 沿着实际 MRO 继续找，也不一定只指向你眼里的“直接父类”。

4.11 什么时候用组合比继承更合适？

答：当两个对象只是合作关系，不是真正的“属于同一种类型”时，组合通常更清楚。

5）线程、进程与协程

5.1 并发和并行，差一个字差在哪里？

答：并发关注多项任务能否一起推进，可以轮流做；并行关注同一时刻是否真的在同时执行。单线程可以在多个等待任务之间切换，做到并发，却不等于同一时刻在多个核心上计算。

5.2 常见 CPython 环境下，多开线程为什么不一定算得更快？

答：通常启用 GIL 的 CPython 中，同一进程在同一时刻通常只有一个线程执行 Python 字节码，所以纯 Python 的 CPU 密集线程难以多核加速。

5.3 有 GIL，就能说 Python 线程永远不能并行吗？

答：不是。原生扩展可能释放 GIL，Python 3.13 起也有可选 free-threaded 构建，但要按解释器和依赖实际验证。

5.4 都说线程适合 I/O 密集任务，原因是什么？

答：线程等待网络、磁盘等 I/O 时，其他线程可以继续工作。

5.5 大部分时间都在计算，通常考虑什么？

答：默认 CPython 下优先考虑多进程、释放 GIL 的原生库或独立计算服务。

5.6 大量任务都在等网络，通常考虑什么？

答：asyncio 和原生异步库。它适合大量等待，不适合直接承载长时间 CPU 计算。

5.7 执行到 await，就一定会切换任务吗？

答：不一定。等待的对象尚未完成、需要挂起时，当前协程才会暂停，让事件循环推进其他任务；如果结果已经就绪，可能直接继续往下走。

5.8 async def 里写 time.sleep，会发生什么？

答：它会把运行事件循环的线程堵住，其他任务也跟着等。模拟异步等待写 `await asyncio.sleep(...)`。函数外面写了 async，不会把里面的阻塞调用自动变成异步。

5.9 Windows 启动多进程，入口为什么要保护起来？

答：把启动入口放进 `if __name__ == "__main__":`，避免子进程重复导入时递归启动。

5.10 用了 asyncio，就一定能撑十万连接吗？

答：不是。实际能力还受内存、文件描述符、连接池、超时、框架和操作系统影响。

6）接口、数据库与项目工具

6.1 Pydantic 该放在请求处理的哪一步？

答：放在数据进入系统的时候，先按模型转换、检查，再交给业务代码。比如确认年龄是合适范围内的整数；但它不能确认对方填写的年龄就是真实年龄。

6.2 Pydantic 模型怎样转成字典或 JSON？

答：model_dump 返回字典，model_dump_json 返回 JSON 字符串。

6.3 FastAPI 怎么知道接口文档应该长什么样？

答：它读取路由、类型提示和 Pydantic 模型，生成 OpenAPI 描述，再展示交互式文档。

6.4 路由什么时候写 def，什么时候写 async def？

答：调用可 await 的异步库时写 async def；只能调用阻塞库时可写普通 def，让框架在线程池处理。

6.5 SQLAlchemy 2 查数据，主要分哪两步？

答：先用 `select(...).where(...)` 描述“要查什么”，再交给 Session 或 AsyncSession 执行。构造查询语句不等于已经访问了数据库。

6.6 几个 gather 任务能共用一个 AsyncSession 吗？

答：不要。每个并发任务应拥有自己的 Session 和事务范围。

6.7 SQLite 配上 aiosqlite，就变成网络异步数据库了吗？

答：不是。aiosqlite 主要通过后台线程包装 SQLite，适合演示和小型场景。

6.8 找依赖和项目配置，应该先看哪个文件？

答：先看 pyproject.toml。可以粗略把它看作 pom.xml 或 build.gradle 的对应物，里面集中放项目基本信息、依赖和工具配置，但具体规则并不完全相同。

6.9 uv.lock 要不要一起提交？

答：应用项目通常应提交，以便不同电脑得到可重复的依赖版本。

6.10 pytest 为什么用普通 assert 也能给出清楚的报错？

答：pytest 会重写 assert，失败时展示更清楚的表达式差异。

6.11 有了 FastAPI，为什么还要 Uvicorn？

答：FastAPI 负责描述路由和处理请求；Uvicorn 是运行 ASGI 应用的服务器，负责把应用接到请求上。开发时可以开 reload 自动重载，生产部署还要考虑进程数、代理和监控。

6.12 相似度分数很高，就代表侵权吗？

答：不代表。它只是文本特征的技术比较结果，不能替代版权归属、授权范围和法律判断。
